# 工作流

1. 校验 breakdown 的项目、源哈希、场景、节拍和证据引用；选择 1–2 场。
2. 检查导演知识目录。只加载 `published` 版本；变化后的未审定版本仅产生警告。
3. 第一轮 Grill：目标、受众、场景、交付物、四象限上下文、条件岗、验收标准。
4. 用户确认后生成 `SceneDirectionRequirementV1` 与 `ExecutionGraphV2`。
5. 常驻岗和已确认条件岗各自输出 `DirectorPositionV1`，用 `AgentResultV1` 包装。
6. 对确有影响的冲突只做一次定向反驳；总导演逐项裁决建议。
7. 第二轮 Grill：每批最多 3 项，直到对白、动作、覆盖、连续性、仪式、可行性等全部拍板；无争议时做整体确认。
8. 先封存规范 JSON并计算 SHA-256，再调度 `$screenplay-shot-prose-compiler` 物化“一镜一段”DOCX。旧项目只有在显式传入 XLSX 参数时才生成兼容镜头表。修改时派生版本。

首次采用新的正文标准，或正文标准版本变化时，正文编译器先交付建立镜、长对白镜、复合调度镜各一条校样；用户确认后再生成全场。

两场始终各自成包。仅当稳定证据证明存在因果、时空、人物状态或叙事关系时，才写桥接说明。
