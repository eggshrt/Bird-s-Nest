# 中文影视制作需求澄清

为口语化、模糊、复合的中文需求做意图识别和澄清，输出可执行的结构化需求。

## 自动触发与筛选

本技能设为自动触发（`allow_implicit_invocation: true`），作为 Skill Orchestrator 的前置筛选器。

**触发后的判断**：
1. **快速识别**：用 20 个 token 内判断输入是否为影视制作需求
2. **非影视需求**：直接返回 `{"intent_type": "not_filmmaking", "pass_through": true}`，不调用后续技能，让对话正常继续
3. **影视需求**：执行完整意图识别与澄清流程，输出结构化需求后调用 `$skill-orchestrator`

**影视制作需求的信号**（任一即判定为是）：
- 提到镜头号/场次/分镜/剧本/角色/场景/道具，或影视平台（即梦、可灵、Seedance、Runway、Pika）
- 提到岗位（导演、摄影、灯光、剪辑、DP、场记）或提示词/图片/视频生成/定妆
- 包含"镜""场""集""幕""分镜""拍""拍摄""剪辑""审片"等关键词

**不介入的场景**：
- 闲聊、问候、元对话，或XX不是影视的"帮我做个XX"
- 通用文案/PPT/海报（除非明确说"用于短剧/视频"），或摄影技巧讨论但不涉及具体项目

## 设计原则

- **慢下来，对的时候**：需求欠指定或有歧义时先澄清，清晰且低风险时直接做。
- **一次一问**：默认每轮只问一个问题，除非是强关联槽位。
- **选项+默认**：封闭问题给预设选项并标记默认值。
- **分档响应**：轻量档只解决歧义，标准档补全槽位，正式档深度面试。

借鉴 interview-me 的 95% 置信度门槛、clarify-idea-skill 的"正确时刻慢下来"哲学、LangGPT 的结构化框架、grill-me 的对抗式提问，以及中文社区的省略主语、程度副词、客气表达处理经验。

## 意图类型（8 类）

1. **单镜优化** (`single_shot_refine`) - 修改单个镜头的某方面（构图/光影/台词/表演/时长）
2. **多镜衔接** (`multi_shot_continuity`) - 检查或修复镜头间连续性/节奏/空间关系
3. **资产设计** (`asset_design`) - 角色定妆、场景、道具、氛围板
   - **槽位补充**：
     - `knowledge_required`: true（标记此需求需查知识库）
     - `knowledge_scope`: "character" | "scene" | "prop"（指定哪个知识库）
4. **提示词生成** (`prompt_generation`) - 输出到 AI 视频平台的提示词
5. **导演会诊** (`director_council`) - 需要多岗位协作评审
6. **剧本拆解** (`screenplay_breakdown`) - 从剧本生成分镜、镜头清单
7. **交付检查** (`delivery_check`) - 校对格式、导出、平台规范、版本封存
8. **元操作** (`meta_operation`) - 查看历史版本、回滚、解释决定、更新项目背景

## 核心槽位

| 槽位 | 必填? | 说明 | 缺失时处理 |
|------|------|------|------------|
| `target_scope` | 是 | 镜头号/范围/资产名 | 从上下文推断；失败则问 |
| `aspect` | 是 | 构图/光影/台词/表演/时长/连续性等 | 从描述词推断；模糊时给选项 |
| `target_platform` | 提示词类必填 | 即梦/可灵/Seedance/Runway | 有默认值时用默认；否则问 |
| `intensity` | 否 | 微调(0.3)/中度(0.5)/重做(0.9) | 从程度副词推断；默认 0.5 |
| `approval_mode` | 否 | 直接改/先建议/会诊 | 从客气程度+复杂度推断 |
| `constraints` | 否 | 时长上限/角色不动/保持某决定 | 不问，从对话累积 |

## 追问规则

直接做：槽位完整 + 单一意图 + 范围明确；用户明确急迫（"直接改""快速出个版本"）；操作可逆低风险。

必须问：指代消解失败（3+ 候选）；程度副词量化失败；复合意图有冲突；涉及实质剧情/人物关系/走位变化。

问题数量：默认一次一问；强关联槽位最多合并 3 个；选项式封闭问题可多项。选项从项目历史决定和行业惯例提取，明确标记默认项，末尾加"或描述具体想要什么"。

## 中文难点处理

### 省略主语与指代

维护指代栈（记录最近 3 轮提到的镜头号、资产名、文件名）：
- "这个/那个/它" → 取栈顶
- "上次/之前" → 取最近一次操作的对象
- "那镜/这镜" → 结合镜头号上下文
- 消解失败 → "'这个'是指镜2还是镜3？"

### 程度副词的模糊要求

程度词典：
- "稍微/微调/小幅" → intensity=0.3（保留 70% 原样）
- "再.../更.../进一步" → intensity=0.5（中度调整）
- "彻底/完全/重做" → intensity=0.9（大改）

领域映射表：
- "高级感" → 光影（HDR/边缘光/体积光）/ 构图（黄金分割/引导线）/ 色调（电影级调色）
- "电影感" → 景深（大光圈虚化）/ 运镜（稳定器/摇臂）/ 节奏（慢镜/长镜头）

澄清策略：给出映射选项 + "或者你说具体想要什么效果"

### 客气/试探式表达

意图判断矩阵：
- "能不能看看" + 无紧迫词 → 建议模式（输出方案不直接改）
- "能不能改成" + 有具体目标 → 执行模式（直接改）
- "要不" + 疑问句 → 征询模式（列出利弊，问是否继续）

确认策略：判断为"试探"时，输出"理解你是想【先看建议】还是【直接改】？"

### 行业黑话

术语表（动态扩展）：
- 平台：即梦(即梦AI)、可灵(可灵AI)、Seedance、Runway、Pika
- 岗位：场记(连续性)、DP(摄影指导)、反打(reverse shot)、定妆(角色外观)
- 流程：分镜(shot breakdown)、导演包(director's package)、提示词(prompt)

自动替换：用户说黑话时内部转为标准术语，输出时保持用户用词习惯。

## 复合需求分解

识别复合标志：
- 连词："还有""顺便""另外""再"
- 多对象："第二镜和第三镜"
- 多方面："光弄高级点，顺便看看跟第三镜接不接得上，出个能直接贴即梦的提示词"

分解策略：
1. 拆成子任务：上例 → ①单镜优化(镜2,光影,高级感) ②衔接检查(镜2→镜3) ③提示词生成(镜2,即梦)
2. 判断依赖关系：①必须先完成，②可并行
3. 询问优先级：如无依赖但资源冲突，问"先做哪个？"
4. 输出执行计划："理解为 3 个子任务，先优化镜2光影，同时检查衔接，最后生成提示词，对吗？"

## 输出格式

**内部结构化输出（仅用于技能间传递，不直接展示给用户）**：

```json
{
  "understanding": {
    "raw_input": "用户原始输入",
    "intent_type": "single_shot_refine",
    "sub_intents": ["优化光影", "生成提示词"],
    "confidence": 0.85
  },
  "slots": {
    "target_scope": "镜2",
    "aspect": "光影",
    "target_platform": "即梦",
    "intensity": 0.5,
    "approval_mode": "先建议"
  },
  "missing_slots": ["光影风格"],
  "questions": [
    {
      "slot": "光影风格",
      "question": "'高级感'是指：A.增强边缘光和体积光 B.提升HDR范围 C.其他（请描述）？",
      "options": ["A", "B", "自定义"],
      "default": "A"
    }
  ],
  "execution_plan": [
    {"step": 1, "task": "澄清光影风格", "status": "pending"},
    {"step": 2, "task": "优化镜2光影", "status": "waiting", "depends_on": [1]},
    {"step": 3, "task": "生成即梦提示词", "status": "waiting", "depends_on": [2]}
  ],
  "context_updates": {
    "reference_stack": ["镜2"],
    "last_operation": "优化光影",
    "project_constraints": ["保持16秒时长", "李博士位置不动"]
  }
}
```

上方 JSON 结构仅供技能内部路由使用，**不得直接输出给用户**。

**用户侧可见的确认消息使用自然语言**，例如：
- 不要："intent_type: single_shot_refine, slots: {target_scope: 镜2}"
- 要："我理解你想优化镜2的光影，对吗？"
- 要："好的，我来帮你优化镜2光影并生成即梦提示词，共3个步骤。"

低置信度时（<0.7）用自然语言直接向用户提问；高置信度时（≥0.9）可跳过确认，直接转发到相应领域技能。

**非影视需求的输出**：
```json
{
  "intent_type": "not_filmmaking",
  "pass_through": true,
  "reason": "闲聊问候 / 通用文案 / ..."
}
```
输出后立即结束，不调用 `$skill-orchestrator`，让对话正常继续。

## 分档行为

- **轻量档**：只解决歧义（指代、程度副词），不追问细节；置信度 ≥ 0.7 即执行。
- **标准档**：补全核心槽位，一次最多问 3 个；置信度 ≥ 0.85 即执行。
- **正式档**：深度面试，挑战假设（"为什么要改这个""不改会怎样"），置信度 ≥ 0.95 才执行。

## 示例

**输入**："把第二镜的光弄高级点，顺便看看跟第三镜接不接得上，出个能直接贴即梦的提示词"

**识别**：
- 意图：单镜优化 + 多镜衔接 + 提示词生成
- 槽位：target_scope=镜2, aspect=光影, target_platform=即梦
- 缺失：光影风格具体指什么

**澄清**（标准档）：
> 理解为 3 个子任务：
> 1. 优化镜2光影（"高级感"）
> 2. 检查镜2→镜3衔接
> 3. 生成即梦提示词
> 
> 先确认一下，"高级感"的光影是指：
> A. 增强边缘光和体积光（电影级光影）【默认】
> B. 提升HDR范围（高动态）
> C. 其他（请描述具体想要什么效果）

**输出**（用户选 A 后）：
```json
{
  "understanding": {"intent_type": "single_shot_refine", "sub_intents": ["优化光影","衔接检查","生成提示词"], "confidence": 0.88},
  "slots": {"target_scope": "镜2", "aspect": "光影", "target_platform": "即梦", "intensity": 0.5, "light_style": "电影级光影"},
  "execution_plan": [
    {"step": 1, "task": "优化镜2光影（电影级）", "domain": "directing", "entry": "screenplay-scene-daoyanzu"},
    {"step": 2, "task": "检查镜2→镜3衔接", "domain": "directing", "entry": "screenplay-scene-daoyanzu", "parallel_with": [1]},
    {"step": 3, "task": "生成即梦提示词", "domain": "prompt_compile", "entry": "asset-driven-cinematic-video-prompt", "depends_on": [1]}
  ]
}
```

转发到 `$screenplay-scene-daoyanzu`（标准档会诊）和 `$asset-driven-cinematic-video-prompt`（提示词）。
